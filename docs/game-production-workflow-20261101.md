採用日期：2026-11-01（America/Phoenix）。作者已指示將參考貼文的適用流程納入本專案；本文件是後續製作規範，不表示下列工具已完成實作。

## 每項功能的工作順序

1. 讀最新入口、玩法狀態與對應權威文件，核對工作副本及未提交變更。劇情查02、採用原圖查03M、角色戰鬥查04A；本流程不改變既有權威來源。
2. 寫清楚玩家行為、合法狀態、轉移條件、資源成本、獎勵與中斷恢復方式，列出必須永遠成立的條件，再動程式。
3. 在隔離資料完成可審閱的小幅變更。每次變更解決明確問題；不以PR數量、檔案數或生成速度衡量完成度。
4. 重現錯誤、修正、留下能攔截同類錯誤的最小有效檢查。可靜態判斷的模式用lint；跨請求、資料與時間的行為用測試，不為每個個案建立脆弱規則。
5. 依風險執行相關測試、狀態／戰鬥驗證、桌機與390px手機實際操作。記錄環境、版本、輸入、結果與未涵蓋範圍；工程測試與美術驗收各自記錄。
6. 檢查效能與載入成本，留下可重現證據。通過必要檢查後按原發布流程備份、還原驗證、提交與部署、讀回版本及部署後備份；發布範圍仍依作者授權。

## 狀態機與不變條件

抽卡保底、升星、裝備轉移、星伴配置、迷航及試煉上下半場優先描述狀態與事件。對重送、並行、切帳號、斷線、重登、舊回應與版本遷移建立必要案例。

至少驗證：資源不為負、扣款與發獎一致、同一結算只能領一次、無資格操作不能生效、一件裝備或一隻星伴不能同時佔用多名角色、試煉整關勝利才計次、切帳號不串存檔、重置只套用授權週期。

複雜且高風險的狀態流程可使用TLA+等模型檢查；先定義模型與性質，再記錄工具版本、搜尋界線及反例。模型檢查通過只代表該模型與界線，不取代API、存檔及實際操作測試。簡單流程使用轉移表與行為測試即可。

## 可重播戰鬥與批量平衡

後續優先建立固定亂數種子的戰鬥重播：輸入包含戰鬥規則版本、種子、角色／技能／命座／升星、裝備、星伴、敵人及必要操作；輸出包含結果、回合數與關鍵事件。模擬邏輯避免依賴畫面幀率、系統時間與未受控亂數。相同版本與輸入應產生相同結果，舊案例必須帶版本。

批量模擬涵蓋新手、一般養成、高養成、三星滿命、不同升星與隊伍協同；統計勝率、回合分布、有效傷害、有效治療、避免傷害、控制與超時／循環。保留失敗種子和最小案例，用於定位反擊、協同、CD重置及星伴觸發問題。先確定樣本數與目標區間，再看結果；不能只挑有利配隊或只堆敵人血量。

模擬結果是平衡證據，仍須實玩確認節奏與可讀性。正式資源與獎勵由後端驗證；如未來增加分數上傳，可評估伺服器重播，不能只信任客戶端分數。重播資料採隔離合成資料，不納入玩家憑證或私人完整存檔。

## 手機效能、載入與素材

先量測再優化。每次重要介面／播放改動記錄裝置或模擬環境、實際viewport、冷載入傳輸量、可互動時間及播放卡頓；模擬尺寸與實體手機結果分開標示。

為首屏腳本、背景與立繪建立本遊戲自己的大小預算，量測基準後才訂門檻。大廳先載必要素材，其餘按頁面載入；需要時採壓縮、快取或圖集。門檻建立後接入建置檢查，超額需說明並修正或記錄有依據的調整。不得直接套用參考遊戲124 KB或500敵人60 fps的目標。

若存在每幀／每tick熱路徑，先用效能量測確認，再減少其中的物件、陣列與閉包配置；可用明確命名與限定範圍的lint規則保護。現有JavaScript專案不必為模仿貼文改成.hot.ts。

音樂轉場與共享素材規格可在需求成立時採用；程式生成像素圖、即時合成音樂與全面自製引擎不是本專案要求。角色衍生素材仍須依03M實看採用圖。保留有助說明設計理由、限制與相容性的註解，避免逐行重述程式。
