# 星界之律｜回覆召集

這是依目前文件與最新指示做出的可執行抽卡系統。`index.html` 是不需要建置工具的瀏覽器試玩介面；抽卡核心位於 `src/gacha.js`，同一份核心也由 Node 內建測試使用。

目前玩家登入後會先進入遊戲大廳，再從大廳前往劇情、抽卡、角色培養與星界試煉；抽卡只是遊戲的一個功能，不會直接取代遊戲入口。

## 現行規則

- 第 1–30 抽：4★ 機率固定為 0%，不會提早出現 4★。
- 第 31 抽：4★ 機率 10%。
- 第 32 抽起：每抽增加 4 個百分點。
- 第 50 抽：100% 硬保底，必定出現 4★。
- 非 4★ 結果中，20% 會抽到文件 1.0–1.5 的三星角色；其餘 80% 轉成 1 回響粉，避免前 30 抽反覆取得同一名三星。
- 4★ 出現後，該類型卡池的保底計數歸零。
- 限定與復刻共用 `limited` 計數；常駐回音召集使用獨立的 `standard` 計數。
- 限定池可從文件 1.0–1.5 的既有 4★ 中選一隻；每次 4★ 判定時，選中者為 55%，其餘 4★ 合計為 45%。未中後下一張 4★ 必定是目前選中的角色，保證不因換池消失。
- 十連只是連續執行十次單格判定，不會把 4★ 延到最後一格。
- 單抽消耗 160 星砂，十連消耗 1,600 星砂；回覆券可抵用一次單抽。
- 重複 4★ 轉為 1 星痕與 50 星砂；重複 3★ 轉為 5 回響粉。
- 目前 active pool 只使用文件 1.0–1.5 已有的 3★／4★；2.0–2.5 的既有角色資料先保留在資料層，等後續補入，不會被本期抽到。

## 劇情、角色與星界試煉

- 目前劇情主線與支線開放文件 1.0–1.5；每一幕第一次完成可獲得 100 星砂，完成紀錄會綁定玩家帳號且不可重複領取。
- 新帳號建立後自動獲得主角瑟蕾雅。完成 1.0 主線任意一幕後，可從雷恩／莉亞中自選一名；星界試煉第 10 關通關後，再自選一名，第二次自選會優先提供尚未取得者。
- 星界試煉採自走棋式自動戰鬥，一次最多派出 4 名已取得角色；目前有 1–10 關，關卡難度逐關提高，必須依序解鎖。
- 目前試煉版本標記為 `1.0-1.5`。每一關在同一版本最多成功領獎 10 次；每次成功固定獲得 100 星砂與 1 張回覆券，失敗不扣次數。下次遊戲更新只要提高版本標記，該版本的各關挑戰／領獎次數就會重置。
- `src/data.js` 集中保存目前開放角色的戰鬥數值、技能、敵人與關卡資料；後續調整平衡時應先改資料層。

## 直接放進網頁使用

玩家頁面現在內建瀏覽器存檔模式，不需要另外啟動 Codex 伺服器。把整個 `gacha-system` 資料夾放到任何靜態網頁空間，讓玩家開啟 `index.html`，首次登入設定名稱與密碼後，抽卡、資源、保底、角色收集與紀錄會保存在玩家自己的瀏覽器中。

也可以直接雙擊 `index.html` 自己試玩；分享時請把整個 `gacha-system` 資料夾一起傳送或整個資料夾上傳，不能只傳單一 `index.html`，因為頁面還需要 `src`、`styles.css` 與 `assets`。若使用公開的 `https://...` 網頁，玩家只要打開同一個網址即可繼續自己的存檔。這種模式是「每位玩家各自保存」，不會把不同玩家的資料互相混在一起。

`start-player.cmd` 現在會直接開啟玩家網頁，不啟動伺服器。`node serve.mjs` 與 `start-admin.cmd` 仍保留作為可選的後端模式：連到後端時，頁面會自動改用伺服器存檔與登入驗證；後端沒有連上時則自動回到瀏覽器本機存檔，不會卡住玩家。

## 玩家存檔與管理端

- 玩家版：`http://127.0.0.1:8080/`，或公開網頁上的 `index.html`。進入前會先詢問「我登入過／第一次登入」；第一次登入設定密碼，之後使用遊戲名稱與密碼登入。
- 製作者測試版：`http://127.0.0.1:8080/test.html`。測試存檔和玩家存檔分開。
- 製作者管理端：`http://127.0.0.1:8080/admin.html`。開發模式管理密鑰是 `dev-admin-key`；公開使用前請設定環境變數 `STARSHIP_ADMIN_KEY`，不要使用這個開發密鑰。
- 玩家資料目前寫入 `data/players.json`，正式公開部署時要選擇有持久化磁碟或資料庫的 Node 託管服務，否則服務重啟可能清掉存檔。

沒有後端時，帳號與存檔使用瀏覽器 `localStorage`；密碼只保存雜湊值。這適合分享給玩家直接遊玩，但製作者管理端無法跨裝置操控本機存檔。若要集中管理所有玩家，才需要再開啟可選的 Node 後端模式。

## 做成可分享網址

這個專案已經是可部署的 Node 網站：啟動命令是 `node serve.mjs`（`npm start` 也會執行同一個命令），服務會使用託管平台提供的 `PORT`，並監聽對外網路。專案內附有 `render.yaml`，可作為 Render Blueprint；它會掛載 `/opt/render/project/src/storage`，並把玩家資料寫到 `/opt/render/project/src/storage/data/players.json`。伺服器也支援用 `STARSHIP_DATA_DIR` 改寫資料目錄，讓其他 Node 託管服務可使用自己的持久化磁碟或資料庫掛載路徑。

正式環境請設定 `NODE_ENV=production`、`STARSHIP_ADMIN_KEY=你自己的長密鑰` 與持久化資料目錄。不要把管理密鑰寫進程式碼或提交到公開儲存庫。部署完成後平台會給一個 `https://...` 網址；把該網址傳給玩家即可，製作者使用同一網址的 `/admin.html`。

注意：GitHub Pages、一般靜態網頁只能放玩家畫面，不能執行這裡的後端存檔與管理 API；要使用名稱存檔和管理端，必須部署 Node 伺服器與持久化資料。
